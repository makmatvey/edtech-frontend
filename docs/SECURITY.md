# Безопасность и персональные данные

«Класна» хранит данные учеников, в том числе несовершеннолетних. Здесь — что хранится, кто что видит,
как ведётся журнал доступа, как делаются резервные копии и что школа должна оформить сама.

## Какие данные хранятся

| Данные | Где | Кто видит |
|---|---|---|
| ФИО, логин, роль | `users` | сам пользователь; учителя своих классов; одноклассники — имя и публичная карточка (фото, рамка, витрина) |
| Хэш пароля (bcrypt) | `users.password_hash` | никто; сам пароль не хранится и не пишется в журналы |
| Фото профиля (по желанию) | `users.avatar` | одноклассники и учителя класса |
| Отметки, посещаемость | `grades`, `attendance` | сам ученик; учителя, которые ведут предмет в классе; классный руководитель — по всему классу |
| Квизы, стрик, отметки о ДЗ | `quiz_attempts`, `streak_days`, `homework_done` | сам ученик; учителя класса — сводно (слабые темы) |

Чего нет: адресов, телефонов, дат рождения, сведений о здоровье, данных родителей — их и не нужно собирать для работы.

## Модель доступа

- Вход по логину и паролю; токен (JWT, 12 ч) подписан секретом сервера. В production секрет обязателен и задаётся только окружением.
- Ученик видит только свой класс и свои данные. Учитель — только уроки и классы, которые ведёт; классный руководитель — весь свой класс.
  Права проверяются на сервере на каждом объекте (урок, класс, ученик), а не только скрытием кнопок в интерфейсе.
- Учебные файлы (`/materials`) — только вошедшим.
- Ограничение попыток входа: 10 за 5 минут с адреса; новый пароль — от 8 символов, буква и цифра.
- Регистрация учителя — только по коду учреждения (`KLASNA_SCHOOL_CODE`), ученика — по коду класса от классного руководителя.

## Журнал доступа (аудит)

Таблица `audit_log`, пишется автоматически:

- любые изменения — входы (в том числе неудачные), регистрации, отметки, посещаемость, ДЗ, профиль, задания;
- любые просмотры учителем (`/api/teacher/…`): журнал, карточки и отметки учеников, выгрузки;
- просмотр карточки одноклассника;
- все отказы в доступе (401/403).

Для каждой записи: время (UTC), пользователь и роль, метод, адрес (без параметров запроса и токенов), код ответа, IP.
Пароли, тела запросов и токены не пишутся. Срок хранения — `KLASNA_AUDIT_DAYS` (по умолчанию 365 дней), старые записи удаляются раз в сутки.

Выгрузка CSV: `npm run audit -- 30` (за 30 дней; в production — `npm run audit:prod -w server -- 30`).

## Резервные копии

- Ежедневно в production (`KLASNA_BACKUP_HOURS`, по умолчанию 24 ч) — целостный снимок SQLite (`VACUUM INTO`) без остановки сервера.
- Хранятся последние `KLASNA_BACKUP_KEEP` копий (по умолчанию 14) в `KLASNA_BACKUP_DIR` (по умолчанию `data/backups`).
- Вручную: `npm run backup` (в production — `npm run backup:prod -w server`).
- Копии лежат на том же диске, что и база, — их нужно регулярно уносить во внешнее хранилище школы
  (например, `rsync`/`rclone` папки `backups` по расписанию). Без этого копия не спасёт от потери диска.
- Восстановление: остановить сервер → скопировать нужный `klasna-*.db` на место `data/klasna.db` → запустить.
  Проверка копии: `sqlite3 klasna-….db "PRAGMA integrity_check"` → `ok`.

## Что оформляет школа (вне кода)

Платформа даёт технические меры, но обработка персональных данных — обязанность оператора, то есть учреждения образования:

- правовое основание обработки и согласия законных представителей учеников — по Закону Республики Беларусь
  «О защите персональных данных» и локальным актам учреждения;
- назначение ответственного за обработку данных и порядок выдачи кодов школы и классов;
- размещение сервера и копий (на территории РБ, если этого требуют правила учреждения), доступ к серверу только у администратора;
- порядок реагирования на инциденты: смена `JWT_SECRET` (все сессии сразу становятся недействительными),
  анализ `audit_log`, уведомление ответственных;
- срок хранения данных выпускников и удаление учётных записей.

## Секреты

- `JWT_SECRET`, `KLASNA_SCHOOL_CODE` — только в окружении или в `.env` (в git не попадает).
- В разработке без `JWT_SECRET` случайный секрет создаётся один раз в `data/.jwt-secret` (папка `data/` в git не попадает).
- Смена `JWT_SECRET` разлогинивает всех — так отзываются все выданные токены.
