# Архитектура «Класны»

## Обзор

```
┌──────────────── Браузер (React SPA) ────────────────┐
│  Вход с выбором роли → кабинет учителя / ученика    │
│  React Router (ленивые страницы) · useApi-хук       │
│  Собственная дизайн-система (CSS-токены, тёмная     │
│  тема, адаптив) · SVG-графики без библиотек         │
└───────────────┬─────────────────────────────────────┘
                │ REST / JSON, JWT в заголовке Authorization
┌───────────────▼─────────────────────────────────────┐
│  Express API (TypeScript)                           │
│  /api/auth     вход, профиль                        │
│  /api/teacher  журнал, расписание, аналитика, КТП   │  ← requireRole('teacher')
│  /api/student  обзор, ДЗ, квиз, стрик,              │  ← requireRole('student')
│                ЦТ/ЦЭ (перевёрнутый урок — в ДЗ)     │
│  services/  quiz (daily/homework/exam) · streak ·   │
│             lessons · flipped                       │
│  Zod-валидация · единый обработчик ошибок           │
└───────────────┬─────────────────────────────────────┘
                │ node:sqlite (встроен в Node ≥ 22)
┌───────────────▼─────────────────────────────────────┐
│  SQLite (WAL, внешние ключи)                        │
│  Источники: profil (программы) · e-padruchnik       │
│  (учебники) · eior / e-vedy / lingvo / апп-бокс     │
│  (ресурсы и банк вопросов)                          │
└─────────────────────────────────────────────────────┘
```

Один процесс отдаёт и API, и собранный клиент — для школы это одна виртуальная машина или контейнер. SQLite выбран осознанно: школа — это сотни, а не миллионы записей в день; при росте до уровня района схема переносится на PostgreSQL без изменения модели (SQL стандартный, доступ к базе изолирован в `db.ts`).

## Модель данных

```
users ─┬─< class_students >── classes ──< teacher_assignments >── subjects
       │                                     │            │
       │                              schedule_slots   curriculum_topics (тема на каждый урок)
       │                                     │            │
       │                                  lessons ────────┘  (дата, тема, ДЗ, «журнал заполнен», флаг «перевёрнутый урок»)
       │                                  │      │
       ├──────────< attendance >──────────┘      │
       ├──────────< grades (1–10, вид) >─────────┘
       ├──< quiz_attempts (вопросы, ответы, балл) ── quiz_questions (предмет, класс, раздел)
       ├──< streak_days (день, источник, XP)
       └──< homework_done
textbooks, resources — каталоги источников (e-padruchnik, eior, e-vedy, lingvo, апп-бокс)
```

Ключевые решения:
- **Тема урока по программе.** При генерации расписания n-й урок предмета в классе получает n-ю тему КТП. Учитель может заменить тему — только на тему из программы своего предмета и класса (проверяется на сервере).
- **Вопросы привязаны к разделу программы.** `quiz_questions(subject, grade, section_no)`. Подбор квиза берёт только вопросы своего класса и разделов `≤` максимального раздела, уже пройденного по журналу (`services/quiz.ts → coverage`). Свежий раздел и предметы с недавним уроком получают больший вес, недавно виденные вопросы — меньший.
- **Стрик считается, а не хранится.** В `streak_days` — только факты «день засчитан» (уникально на ученика и дату). Длина серии, заморозки и календарь вычисляются функцией `streakState` по учебному календарю РБ (каникулы и праздники в `calendar.ts`), поэтому правила можно менять без миграции данных.
- **Проверка на сервере.** Клиент получает вопросы без правильных ответов; `submitAttempt` в транзакции проверяет ответы, начисляет день только за первую успешную попытку данного типа, повторная отправка — 409.

## Безопасность и надёжность
- JWT (12 ч); секрета по умолчанию в коде нет: в production `JWT_SECRET` (≥ 32 символов) обязателен, в разработке случайный секрет создаётся в `data/.jwt-secret`. В production обязателен и `KLASNA_SCHOOL_CODE`. Пароли bcrypt (сравнение асинхронное, не блокирует сервер); новый пароль — от 8 символов, с буквой и цифрой.
- Ограничение попыток входа (10 за 5 минут с IP); за прокси реальный IP берётся из `X-Forwarded-For` при заданном `TRUST_PROXY`. CORS — адреса из `CORS_ORIGIN` (по умолчанию localhost).
- Файлы `/materials/*` — только вошедшим: токен в `Authorization` или в `?token=` (теги `<video>`, `<img>`, `<iframe>` не шлют заголовки), `Cache-Control: private`.
- Демо-данные на пустой базе создаются сами только вне production (или при `KLASNA_DEMO=1`).
- Ролевой доступ на уровне роутера + проверка владения на каждом объекте: учитель видит только свои уроки и классы (классный руководитель — весь класс), ученик — только свой класс.
- Все входные данные валидируются Zod, ошибки возвращаются на русском, без утечки внутренностей.
- Журнал сохраняется одной транзакцией; оценки и посещаемость нельзя поставить за будущий урок.
- Журнал доступа `audit_log` (`server/src/audit.ts`): изменения, просмотры учителем, отказы 401/403 — без паролей и токенов; срок хранения `KLASNA_AUDIT_DAYS`.
- Резервные копии (`server/src/backup.ts`): `VACUUM INTO` по расписанию с ротацией, вручную — `npm run backup`.
- Production: сервер собирается `tsc` в `server/dist` и запускается обычным `node` (без `tsx`); `package-lock.json` в репозитории; Docker — один контейнер на школу (docs/DEPLOY.md).
- Сквозные тесты (`server/src/*.test.ts`) — права, журнал, квиз, стрик, согласованность данных, безопасность, бэкапы и аудит.

## Производительность
- Клиент: ~66 КБ gzip основного бандла, страницы грузятся лениво; шрифты локальные (@fontsource), без внешних CDN — работает в закрытой школьной сети.
- Сервер: индексы по датам уроков, ученику и попыткам; ответы API 4–25 мс на обычном ноутбуке (замер на демо-базе: 800 уроков, 10 000 отметок посещаемости).

## Структура репозитория
```
server/src/
  app.ts, index.ts       — Express-приложение и запуск
  ensure-db.ts           — подготовка базы data/klasna.db: создать и засеять, если пуста; иначе сохранить данные
  db.ts, calendar.ts     — схема/миграция, учебный календарь РБ
  auth.ts, http.ts       — JWT, роли, ошибки, валидация
  routes/                — auth, teacher, student
  services/              — quiz, streak, lessons
  data/                  — программы (КТП), банк вопросов, учебники, ресурсы, демо-школа
  seed.ts                — генерация демо-данных через те же сервисы, что и API
  api.test.ts            — сквозные тесты
client/src/
  pages/teacher|student  — экраны кабинетов
  components/            — UI-кит, графики, квиз, карточки уроков
  lib/                   — API-клиент, авторизация, хуки, форматирование
  styles/app.css         — дизайн-система
```
