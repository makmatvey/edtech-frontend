# Развёртывание «Класны»

## Модель: одна школа — один экземпляр

Каждая школа работает в своём экземпляре сервера со своей базой SQLite, своим кодом школы и своим секретом токенов.
Так данные школ (а это данные несовершеннолетних) разделены физически: ошибка доступа или утечка в одной школе
не открывает данные другой, резервные копии и журнал доступа — у каждой свои, а нагрузка одной школы
(≈ 1000 учеников, сотни запросов в минуту) с запасом укладывается в один процесс Node.js и SQLite в режиме WAL.

Несколько школ на одном сервере — несколько контейнеров за обратным прокси (пример — `docker-compose.example.yml`):

```
            HTTPS                      ┌──────────────────────────┐
school12.example.by ──┐                │ klasna (school12) :3101  │── том school12-data (база, копии, журнал)
                      ├─ Nginx/Caddy ──┤                          │
gym5.example.by ──────┘                │ klasna (gym5)     :3102  │── том gym5-data
                                       └──────────────────────────┘
```

Что не проверено и требует отдельной работы перед подключением многих школ: нагрузочное тестирование на реальных
данных, централизованный мониторинг и сбор журналов со всех экземпляров, единый вход (SSO) для учителей нескольких
школ. Переход к общей базе на много школ (PostgreSQL + `school_id` в каждой таблице) возможен, но для школьных данных
изоляция экземпляров проще и безопаснее.

## Production-запуск без tsx

Сервер собирается в обычный JavaScript; в рабочей установке нет ни `tsx`, ни `typescript`:

```bash
npm ci                        # все зависимости — для сборки
npm run build                 # client/dist + server/dist
npm ci --omit=dev -w server --include-workspace-root=false   # на сервере: только зависимости рантайма
NODE_ENV=production JWT_SECRET=… KLASNA_SCHOOL_CODE=… npm start   # node server/dist/index.js
```

`package-lock.json` хранится в репозитории — `npm ci` ставит ровно те же версии, сборки воспроизводимы.

Docker (то же самое в два этапа):

```bash
docker build -t klasna .
docker run -d --name school12 -p 127.0.0.1:3101:3001 -v school12-data:/app/data \
  -e JWT_SECRET="$(openssl rand -base64 48)" -e KLASNA_SCHOOL_CODE=SCHOOL12-XXXX -e TRUST_PROXY=1 \
  -e CORS_ORIGIN=https://school12.example.by klasna
```

## Обязательные настройки

| Переменная | Зачем |
|---|---|
| `NODE_ENV=production` | боевой режим: без настроек ниже сервер не стартует, демо-аккаунты сами не создаются |
| `JWT_SECRET` | подпись токенов входа, не короче 32 символов (`openssl rand -base64 48`). Значения по умолчанию в коде нет |
| `KLASNA_SCHOOL_CODE` | код учреждения, который учителя вводят при регистрации (от 6 символов, не демо-код) |
| `CORS_ORIGIN` | адрес сайта школы, например `https://school12.example.by` |
| `TRUST_PROXY` | `1`, если перед сервером один прокси (Nginx/Caddy) |

Резервные копии и журнал — см. [SECURITY.md](SECURITY.md).

## Обновление версии

1. `npm run backup:prod -w server` (или дождаться ежедневной копии).
2. Собрать и запустить новую версию — схема базы досоздаётся автоматически, данные сохраняются.
3. Проверить `GET /api/health`.
